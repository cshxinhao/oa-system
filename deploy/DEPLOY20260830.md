# DEPLOY 2026-08-30：请假系统优化（自选审批人 + 全局审批人 + 年假额度）

本次更新包含 3 项功能 + 1 项计算规则调整：

1. **自选审批人**：员工提交请假时从候选列表选择审批人（部门负责人 / 上级部门负责人 + 全局审批人），不再自动路由；原 `reviewer` 字段保留为"实际处理人"记录（全局审批人或超管代批时二者不同）
2. **全局审批人**：`User.can_approve_all_leaves` 布尔标记，超管在 admin 后台设置；被标记的员工可审批所有人的请假（解决无部门员工无人可批的问题）
3. **年假额度**：`LeaveQuota` 模型（人/年/假种），提交年假时余额不足禁止提交；leave management 新增 **Leave Quota** tab（最左侧）展示本人额度
4. **周末不计入请假天数**：所有假种的请假时长均按工作日计算（周六日排除）；年假额度扣减与提交校验同此规则，年假纯周末区间禁止提交

## 一、备份数据库（必做）

本次有 3 个迁移（含 1 个数据迁移），操作前先手动备份一次。

> 注意：数据盘平时属主是 `www-data`（见 DEPLOY.md 更新流程），devuser 直接写 `/data/oa-system` 会报
> `Error: cannot open ...`。先执行下一步的 chown 再备份即可：

```bash
sudo chown devuser:devuser /data/oa-system /data/oa-system/db.sqlite3
sqlite3 /data/oa-system/db.sqlite3 ".backup '/data/oa-system/backups/db-pre-20260830.sqlite3'"
ls -l /data/oa-system/backups/db-pre-20260830.sqlite3   # 确认文件存在且大小与 db.sqlite3 接近
```

## 二、更新代码与迁移

无新增 Python 依赖（`requirements.txt` 未变），无需 `pip install`。执行：

```bash
cd /opt/oa-system/current
git pull

# 关键：手动跑 manage.py 前必须加载环境变量，
# 否则 DJANGO_SQLITE_PATH 未生效，migrate 会打到 /opt/oa-system/current/db.sqlite3（误建新库）
set -a
. /opt/oa-system/.env
set +a
# 可选：确认数据库路径指向 /data/oa-system/db.sqlite3
/opt/oa-system/venv/bin/python manage.py shell -c "from django.conf import settings; print(settings.DATABASES['default']['NAME'])"

sudo chown devuser:devuser /data/oa-system /data/oa-system/db.sqlite3
/opt/oa-system/venv/bin/python manage.py migrate
/opt/oa-system/venv/bin/python manage.py collectstatic --noinput
sudo chown -R www-data:www-data /data/oa-system
sudo systemctl restart oa-system
sudo systemctl status oa-system --no-pager
```

## 三、部署后 admin 后台配置（必做）

用超管账号登录 `https://<域名>/admin/`：

### 1. 设置全局审批人（如有需要）

`Core → Users` → 选择员工 → 勾选 **Can Approve All Leaves** → 保存。

被勾选的员工会出现在所有员工的审批人下拉中，并能看到/审批全部待审批请假。

### 2. 为所有员工配置年假额度（重要！）

`Core → Users` → 选择员工 → 页面底部 **Leave Quotas** 内联表格 → 添加一行（Year=2026，Leave Type=Annual Leave，Total Days=额度）→ 保存。

或在 `Hr → Leave quotas` 列表页统一添加。

> ⚠️ 未配置当年年假额度的员工，提交年假会被阻止并提示
> "No annual leave quota has been configured for you."
> 其他假种（病假等）不受影响，可后续分批配置。

### 3. 历史数据说明

- 历史已处理申请的审批人记录完整保留：`reviewer`（实际处理人）原值未动，`approver` 由原 `reviewer` 值回填
- 旧版本遗留的 **pending 申请没有 approver**（旧流程不记录），仍可被超管/全局审批人/部门经理处理；建议让员工撤回后重新提交，新申请会走新流程

## 四、验证清单

1. 普通员工（有部门）：请假表单审批人下拉**预选**了部门负责人，可正常提交
2. 无部门员工：下拉出现所有全局审批人，可正常提交（若下拉为空，检查全局审批人是否已设置）
3. 部门负责人 / 全局审批人：待审批 tab 能看到申请并批准/拒绝；员工"我的申请"里 Approver（所选）与 Reviewer（实际）两列正确
4. 年假：提交超过余额的申请被阻止并显示剩余天数；批准后 Leave Quota tab 和年假 tag 数字正确；跨周末的年假按工作日扣减
5. Dashboard 待办中的请假审批仍正常

## 五、回滚

若出现问题：

```bash
# 恢复数据库备份
sudo systemctl stop oa-system
sqlite3 /data/oa-system/db.sqlite3 ".restore '/data/oa-system/backups/db-pre-20260830.sqlite3'"

# 代码回退到上一个版本
cd /opt/oa-system/current
git log --oneline -3          # 找到更新前的 commit
git checkout <更新前的commit>

sudo systemctl start oa-system
```

> 注意：回滚数据库后，`hr_leavequota` 等新表将不存在，代码必须同步回退，否则页面会报错。
