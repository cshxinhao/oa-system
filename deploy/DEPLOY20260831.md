# DEPLOY 2026-08-31：请假系统优化（按人配置 eligible approvers）

本次更新包含 1 项功能：

1. **按人配置 eligible approvers**：admin 后台 `Hr → Leave approver settings`（或 `Core → Users` 列表的 **Leave Approvers** 链接）可为每个员工配置其请假可选审批人列表；新增配置时默认预填部门负责人（本人是部门负责人时预填上级部门负责人），管理员可增删任意人选。保存后该列表**完全取代**默认组织路由；列表留空 = 该员工仅可选全局审批人。全局审批人（`can_approve_all_leaves`）机制不变，始终自动对所有人生效，无需逐个配置。

## 一、备份数据库（必做）

本次仅 1 个建表迁移（无数据迁移），但操作前仍先手动备份一次。

> 注意：数据盘平时属主是 `www-data`（见 DEPLOY.md 更新流程），devuser 直接写 `/data/oa-system` 会报
> `Error: cannot open ...`。先执行下一步的 chown 再备份即可：

```bash
sudo chown devuser:devuser /data/oa-system /data/oa-system/db.sqlite3
sqlite3 /data/oa-system/db.sqlite3 ".backup '/data/oa-system/backups/db-pre-20260831.sqlite3'"
ls -l /data/oa-system/backups/db-pre-20260831.sqlite3   # 确认文件存在且大小与 db.sqlite3 接近
```

## 二、更新代码与迁移

无新增 Python 依赖（`requirements.txt` 未变），无需 `pip install`。

> ⚠️ 本次改动（含本文件）当前仍是本地未提交状态：先在本地
> `git add` + `git commit` + `git push`，服务器 `git pull` 才能拉到新代码。

执行：

```bash
cd /opt/oa-system/current
git pull

# 关键：手动跑 manage.py 前必须加载环境变量，
# 否则 DJANGO_SQLITE_PATH 未生效，migrate 会打到 /opt/oa-system/current/db.sqlite3（误建新库）
set -a
. /opt/oa-system/.env
set +a
# 可选：确认数据库路径指向 /data/oa-system/db.sqlite3
/opt/oa-system/venv/bin/python manage.py shell -c "from django.conf import settings; print(settings.DATABASES['default']['NAME'])"

sudo chown devuser:devuser /data/oa-system /data/oa-system/db.sqlite3
/opt/oa-system/venv/bin/python manage.py migrate
/opt/oa-system/venv/bin/python manage.py collectstatic --noinput
sudo chown -R www-data:www-data /data/oa-system
sudo systemctl restart oa-system
sudo systemctl status oa-system --no-pager
```

## 三、部署后 admin 后台配置（可选）

**本次无必做配置**：未配置任何行时，行为与上一版本完全一致（默认部门负责人路由）。

按需配置某员工的 eligible approvers：

1. `Core → Users` → 员工行的 **Leave Approvers** 列点 **Configure**（或 `Hr → Leave approver settings` → Add）
2. 表单已预选该员工与默认审批人（部门负责人；本人是部门负责人时为上级部门负责人）
3. 增删人选后保存；已配置的行显示为 "N approver(s)"，点击可继续编辑

> ⚠️ 保存后该列表**完全取代**默认组织路由：移除部门负责人后其不再可选；列表留空 = 该员工仅能选择全局审批人（无全局审批人时无法提交，员工会看到提示）。
> 全局审批人（`Core → Users` → **Can Approve All Leaves**）不受影响，始终自动出现在所有员工的候选列表中。

## 四、验证清单

1. admin 后台 `Hr` 分区出现 **Leave approver settings**；`Core → Users` 列表出现 **Leave Approvers** 列
2. 点 **Configure**：员工已预选、部门负责人已在 Chosen 列表（部门负责人本人配置时预填上级部门负责人）
3. 移除部门负责人并保存空列表 → 该员工下拉仅剩全局审批人（或为空并提示联系管理员）
4. 配置任意非经理用户为审批人 → 该员工提交时选择 TA → TA 在待审批 tab 和 Dashboard 看到并可批准（Approver=所选人，Reviewer=实际处理人）
5. 未配置的员工行为不变（预选部门负责人）；全局审批人仍出现在所有人下拉中

## 五、回滚

若出现问题：

```bash
# 恢复数据库备份
sudo systemctl stop oa-system
sqlite3 /data/oa-system/db.sqlite3 ".restore '/data/oa-system/backups/db-pre-20260831.sqlite3'"

# 代码回退到上一个版本
cd /opt/oa-system/current
git log --oneline -3          # 找到更新前的 commit
git checkout <更新前的commit>

sudo systemctl start oa-system
```

> 注意：回滚数据库后，`hr_leaveapproversetting` 等新表将不存在，代码必须同步回退，否则页面会报错。
