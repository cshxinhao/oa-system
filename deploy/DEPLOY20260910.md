# oa-system 部署记录 — 2026-09-10：请假审批邮件通知

本次发布为请假系统增加邮件通知：

1. 员工提交请假申请 → 选中的审批人收到提醒邮件
2. 审批完成（批准/拒绝）→ 申请人收到结果邮件

邮件通过 [Resend](https://resend.com)（第三方 SMTP 中继，587/STARTTLS）以 `leave@avenue.limited` 发件，请求内同步发送，发送失败不影响业务流程（仅记录日志）。

## 前置条件

### 1. 代码已提交并推送（部署前必须完成）

本地当前改动尚未提交，需先执行：

```bash
git add oa_system/settings.py apps/hr/views.py apps/hr/mail.py apps/hr/test_mail.py deploy/.env.example deploy/DEPLOY.md deploy/DEPLOY20260910.md
git commit -m "add leave approval email notifications"
git push
```

### 2. Resend 发信凭据（见 `DEPLOY.md`「邮件通知（Resend）」章节）

- [ ] 公司已有 Resend API Key（发件域名 `avenue.limited` 需已在 Resend 控制台验证）
- [ ] API Key 填入服务器 `/opt/oa-system/.env` 的 `EMAIL_HOST_PASSWORD`（只放服务器 `.env`，不要提交进仓库）

> 未配置前，部署后邮件发送会失败（仅记录日志，不影响请假功能本身，可以照常发布代码）。

### 3. 员工邮箱完整性检查

邮件按 `User.email` 发送，**邮箱为空的用户收不到任何邮件**。部署后执行下方「部署后检查」第 2 条，为所有在职员工补全真实邮箱。

## 部署步骤（服务器操作）

```bash
# 1. 拉取代码
cd /opt/oa-system/current
git pull

# 2. 安装依赖（本次无新增依赖，执行无害）
/opt/oa-system/venv/bin/pip install -r requirements.txt

# 3. 迁移（本次无迁移文件，执行无害）
set -a
. /opt/oa-system/.env
set +a
/opt/oa-system/venv/bin/python manage.py migrate

# 4. 重启服务
sudo systemctl restart oa-system
sudo systemctl status oa-system --no-pager
```

### 5. 配置 .env（拿到 API Key 后执行）

编辑 `/opt/oa-system/.env`，确认以下项（模板见 `deploy/.env.example`）：

```
EMAIL_HOST=smtp.resend.com
EMAIL_PORT=587
EMAIL_USE_TLS=1
EMAIL_HOST_USER=resend
EMAIL_HOST_PASSWORD=<Resend API Key>
EMAIL_DEFAULT_FROM=leave@avenue.limited
EMAIL_TIMEOUT=15
SITE_URL=https://oasystem.avenue.limited
```

修改后重启：`sudo systemctl restart oa-system`

### 6. SMTP 冒烟测试

```bash
cd /opt/oa-system/current
set -a
. /opt/oa-system/.env
set +a
sudo -u www-data /opt/oa-system/venv/bin/python manage.py shell -c \
  "from django.core.mail import send_mail; send_mail('OA mail test', 'Test body', 'leave@avenue.limited', ['your-address@avenue.com'], fail_silently=False)"
```

收到测试邮件即 SMTP 配置正确。

## 部署后检查

1. **服务健康**：`sudo systemctl status oa-system`；`sudo journalctl -u oa-system -n 50` 无异常堆栈
2. **员工邮箱清单**（重点！）：

   ```bash
   sudo -u www-data /opt/oa-system/venv/bin/python /opt/oa-system/current/manage.py shell -c \
     "from core.models import User; \
      print('\n'.join(f'{u.username}  ({u.get_full_name()})' for u in User.objects.filter(is_active=True) if not u.email) or 'all users have email')"
   ```

   输出的用户需在 admin 后台补全真实邮箱（注意域名：员工实际收件域名，如 `@avenue.com`）
3. **端到端验证**：用两个真实账号走一遍提交请假 → 审批人收邮件 → 批准/拒绝 → 申请人收邮件
4. **失败日志监控**：`sudo journalctl -u oa-system -f | grep "Failed to send"`（正常应无输出）

## 回滚方案

邮件通知与业务逻辑解耦（发送失败仅记日志、状态机转换失败自动不发邮件），风险很低。如需回滚：

```bash
cd /opt/oa-system/current
git checkout <上一个 commit>
sudo systemctl restart oa-system
```

无需数据库回滚（无迁移）。
